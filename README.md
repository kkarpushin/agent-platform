# Маяк — рабочая AI-система

Расширяемая учебная основа с **девятью слоями**, графическим интерфейсом и настоящей моделью через авторизованный **Claude Code CLI или Codex CLI**. Дайте поручение, добавьте знания и способы работы, проверьте результат. Компания, сотрудники и сообщения вымышлены.

## Запуск одной командой

Нужны Python 3.10+, работающий Docker с Compose 2.24.4+ и вход через аккаунт в Claude Code 2.1.303+ либо Codex 0.154.0+. [Установка и вход](docs/cli-setup.md).

```bash
python3 scripts/start.py --provider claude
```

Для Codex замените `claude` на `codex`; в маршруте Windows через WSL запускайте эту же команду в Ubuntu. Откройте **http://127.0.0.1:8080** и оставьте терминал работающим. Если порт занят, добавьте `--port 8081`. Первый запуск собирает контейнеры. **Ctrl+C** останавливает приложение и исполнителя, сохраняя данные. Повторите команду для продолжения.

Версия 0.2 использует отдельное хранилище `mayak-agent-platform-v2`; версия 0.1 и её история не мигрируют автоматически. `docker compose up` запускает части приложения, но для ответов модели дополнительно нужен исполнитель CLI; команда выше делает оба шага.

## Первый проход

В «Скиллах» от имени Марка выберите **«Объяснение процесса» → «Использовать»**. Замените пример вопросом: **«Кто утверждает срок Орбиты? Можно ли обещать пятницу?»** Нажмите **«Выполнить поручение»**. Помощник применит выбранный скилл и сохранит ответ. Посмотрите источники в блоке «Как получен результат», затем найдите соответствующее правило в «Знаниях». На главной можно также оставить автоматический выбор способа работы.

В «Процессы» обработайте **E001** → прочитайте предложение → выберите Анну и примите точную версию → найдите **TASK-E001**. Затем обработайте **E002**, примите обновление и сравните историю той же задачи. До решения человека доска не меняется. Внешних отправок нет.

## Девять слоёв

| Слой | Где смотреть |
|---|---|
| Цели и люди | `config/goals.yaml`, `config/people.yaml` |
| Роли и полномочия | `config/roles.yaml`, серверные проверки |
| Знания и информация | `knowledge/`, поиск PostgreSQL, источники запуска |
| Скиллы | `skills/`, выбранная инструкция и её версия |
| Агенты и модели | `agents/`, общий исполнитель и CLI |
| Инструменты и доступы | `compose.yaml`, временные пропуски, локальный исполнитель |
| Процессы | `processes/`, входящие, решение и общая доска |
| Запуск и состояние | `platform/`, версии задач и история |
| Проверка и улучшение | `tests/`, журнал, решения и память |

## Добавляйте своё

- **Знание:** создайте файл по образцу `knowledge/<раздел>/`, затем синхронизируйте от Анны.
- **Сотрудник:** добавьте запись в `config/people.yaml` с существующей ролью, затем синхронизируйте.
- **Скилл:** добавьте `skills/<имя>/SKILL.md` с `execution: draft`, понятным `title`, ролями и контекстом; синхронизируйте и выполните через общий исполнитель. Ядро менять не нужно. [Пример](docs/add-skill.md).
- **Агент или новое действие:** подключите программу по контракту входа/выхода и проверьте права. [Инструкция](docs/add-agent.md).

Универсальна основа и способ расширения. Текстовая инструкция не подключает сервис и не выдаёт новые полномочия. Диспетчер готовит ответ или предлагает следующий маршрут; изменение задачи требует отдельного запуска и решения человека. [Архитектура и границы](docs/architecture.md).

`make test` проверяет код в отдельном окружении с контролируемыми ответами, сохраняя рабочую базу. [Команды без Make и состав проверок](docs/testing.md). Настоящие модельные вызовы проверяются отдельно. Если CLI недоступен, система показывает ошибку; готовый шаблон вместо ответа не появляется. [Подключение и лимиты](docs/model-and-access.md).

Дальнейшие расширения: поиск по смыслу, подключаемые внешние инструменты, корпоративный вход, фоновые процессы и расписание. Учебный переключатель сотрудников не удостоверяет личность; используйте вымышленные локальные данные.
