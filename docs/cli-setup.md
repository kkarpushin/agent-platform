# Вход в модель и запуск системы

CLI — программа, которой дают команды в терминале. Выберите **Claude Code или Codex**. Подписка должна давать доступ к выбранному инструменту; отдельный API-ключ в этом уроке не требуется. Не копируйте токены входа в чат, исходники или настройки агента.

## 1. Установите один инструмент и войдите

**Claude Code:** установите по [официальной инструкции](https://code.claude.com/docs/en/setup), выполните `claude`, затем войдите в аккаунт Claude. Проверка: `claude auth status`. Для этого каркаса нужна версия **2.1.303 или новее**: в ней доступны используемые ограничения инструментов и пользовательских настроек.

**Codex:** установите по [официальной инструкции](https://learn.chatgpt.com/docs/cli), выполните `codex login` и выберите вход через ChatGPT. Проверка: `codex login status`. Нужна версия **0.154.0 или новее** с запуском без пользовательской конфигурации.

Версию покажут `claude --version` и `codex --version`. Сначала обновите старый CLI официальным способом; платформа сама ничего не устанавливает и не меняет настройки аккаунта.

## 2. Подготовьте среду один раз

Нужны Python 3.10+ и работающий Docker Desktop либо Docker Engine с Compose 2.24.4+. Docker запускает готовые части системы в отдельных контейнерах; модель работает через CLI на вашем компьютере. Для Windows удобнее использовать WSL 2: установите Python и выбранный CLI внутри WSL и включите интеграцию Docker Desktop с WSL. Вход, проверку и запуск выполняйте в одном окружении.

Откройте терминал в папке скачанного репозитория. На macOS/Linux/WSL обычно используется `python3`, на Windows с Python Launcher — `py -3`.

## 3. Запустите одной командой

С Claude Code:

```bash
python3 scripts/start.py --provider claude
```

Или с Codex:

```bash
python3 scripts/start.py --provider codex
```

Команда проверяет установку и вход, создаёт в `.env` только локальный пропуск для связи частей системы, запускает контейнеры и рабочий процесс CLI. Откройте **http://127.0.0.1:8080**. Оставьте терминал открытым. Первый запуск скачивает образы и собирает приложение, поэтому может занять несколько минут.

**Ctrl+C** останавливает рабочий процесс и контейнеры; задачи, знания и история остаются. Следующий запуск той же команды продолжит работу на сохранённых данных. Если порт занят, добавьте `--port 8081` и откройте указанный адрес.

Версия 0.2 использует отдельный проект `mayak-agent-platform-v2`, чтобы не смешивать данные с версией 0.1. Это не автоматическая миграция старых запусков. Дополнительное имя можно выбрать через `--project`, но это создаст отдельную базу.

## Как проверить подключение

`python3 scripts/start.py --provider claude --check` проверяет среду и вход, но ещё не обращается к модели. Успешная реальная проверка — запустить агента в интерфейсе, получить результат и открыть журнал: там должны быть провайдер, ответ модели, время и фактически сообщённые токены. Доступность рабочего процесса сама по себе этого не доказывает.

Если вход истёк, закончился лимит или модель недоступна, система покажет ошибку. Войдите в CLI вручную, перезапустите команду и осознанно повторите запрос. Заготовленный текст вместо ответа модели не появляется. Неудачный или прерванный запрос мог уже использовать лимит подписки; автоматического повторного обращения к модели нет.

## Если запускаете части отдельно

Основной путь выше проще. Для диагностики можно оставить контейнеры работающими и запустить только `scripts/cli_worker.py --provider claude --url http://127.0.0.1:8080`. При этом `CLI_WORKER_TOKEN` должен быть передан из локального `.env` через окружение; не вставляйте его в аргументы команд и не публикуйте. Ключ модели или файл входа для этого не нужен.
