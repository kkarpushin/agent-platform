# Проверки кода и настоящей модели

`make test` запускает отдельный проект `mayak-platform-tests` с `LLM_MODE=fixture`, контролируемыми ответами и собственной базой. Он не вызывает CLI, не занимает порт 8080 и не меняет рабочие задачи. По завершении удаляется только тестовая база. В PostgreSQL-тестах используются отдельные случайные схемы.

Нужен Docker Compose 2.24.4+ (`!reset` отключает публикацию порта). Без Make, если доступен shell: `sh scripts/test.sh`.

## Без Make и shell

Выполните по очереди из корня репозитория:

```text
docker compose -p mayak-platform-tests -f compose.yaml -f compose.test.yaml --profile test up --build -d --wait db task-intake daily-brief work-assistant platform
docker compose -p mayak-platform-tests -f compose.yaml -f compose.test.yaml --profile test run --build --rm tests
docker compose -p mayak-platform-tests -f compose.yaml -f compose.test.yaml --profile test down -v
```

Последняя команда удаляет только данные указанного тестового проекта. Не переносите `-v` в обычный перезапуск.

## Что проверять

- Права роли, разрешённые разделы, привязанный и динамический скилл, закрытые записи и временные токены.
- Настоящие HTTP-сервисы агентов и PostgreSQL; контракт входа/выхода и фактические источники.
- Предложение без изменения задач; принятие точной версии; история; обновление той же задачи.
- Повторы события и запроса, конфликт входов, изменившаяся задача/источник и восстановление.
- Протокол локального исполнителя: ограничение команд, разбор ответа, отсутствие подмены при ошибке, учёт фактических сведений.

HTTP-набор проверяет режим сервера до первого обращения к агенту и отказывается работать с основной CLI-системой. Контролируемый ответ проверяет код, а не качество живой модели.

## Настоящая модель

Запустите `scripts/start.py` с авторизованным CLI. Выполните поручение через интерфейс и проверьте модельный вызов, источники, ответ, время и доступные данные об использовании. Для полного процесса отдельно проверьте E001 → решение → задача → E002 → новая версия и новый скилл после синхронизации. Не утверждайте, что такой прогон выполнен, по одному успешному тестовому набору.

Браузерная проверка форм: `tests/browser_schema.py` при установленном Playwright. Фактическая авторская приёмка конкретного выпуска: [validation.md](validation.md).
