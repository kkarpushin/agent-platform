# Настоящая модель и доступ

## Как работает основной путь

Вы входите в Claude Code или Codex на своём компьютере. `python3 scripts/start.py --provider claude` (либо `codex`) запускает платформу и небольшой **рабочий процесс** — программу, которая забирает запросы к модели из очереди и возвращает ответы. Подробные шаги находятся в [инструкции запуска](cli-setup.md).

Последовательность: агент → шлюз модели платформы → очередь → авторизованный CLI → ответ → журнал. Шлюз — единая точка, через которую агенты обращаются к модели. Вход в аккаунт хранится обычным способом самого CLI; платформа не читает, не копирует и не передаёт файл авторизации контейнерам. Локальный `CLI_WORKER_TOKEN` в `.env` — пропуск только между платформой и рабочим процессом, а не ключ Anthropic или OpenAI.

В основном режиме `LLM_MODE=cli` нет шаблонной подмены ответа. Без рабочего процесса, входа, доступной модели или лимита запрос заканчивается ошибкой. Тесты используют явно обозначенные контролируемые ответы и не проверяют доступность вашего аккаунта.

## Что получает модель

Агент получает документы только через платформу: одновременно учитываются роль человека и разделы, объявленные агентом. В CLI уходят выбранные фрагменты и вход текущего запроса. Рабочая папка каждого обращения — новая временная папка, а не репозиторий компании.

Claude Code запускается с `--safe-mode`, `--restricted`, пустым списком инструментов, отключёнными скиллами и MCP, без сохранения диалога. Codex — с `--ignore-user-config`, `--ephemeral`, отключёнными командами, приложениями, плагинами, памятью, браузером, делегированием и локальными изображениями. Загрузка пользовательских документов отключена. Системные инструкции ограничены задачей платформы; клиентские сообщения рассматриваются как данные. Никакие глобальные настройки CLI и подтверждений не меняются.

Это учебный адаптер для собственного доверенного компьютера и проверенной версии CLI. Администраторские политики CLI продолжают действовать. Прямой владелец файлов компьютера всё равно может их читать: эта схема не превращает личный ноутбук в многопользовательский защищённый сервер. Для корпоративного сервера нужны отдельные служебные учётные записи, изоляция и проверенная политика доступа.

## Ограничения и журнал

Один запрос: до 180 секунд, ограниченный объём входа и ответа. Запрос закрепляется за одним рабочим процессом; после сбоя он не выдаётся другому автоматически. Повтор передачи готового ответа допустим, повторного платного вызова из-за ошибки передачи нет. При остановке дочерний CLI завершается вместе с рабочим процессом.

В журнал сохраняются текст, время, провайдер и токены, сообщённые CLI. Для Claude входные токены включают обычный ввод и сообщённые чтение/создание кеша; детали сохраняются отдельно. Если CLI не сообщает точное имя модели, так и написано: «модель не сообщена». Число токенов — факт ответа CLI, а не оценка по символам.

**Стоимость запроса через подписку неизвестна.** Показатель оценочной стоимости, который может возвращать Claude Code, не равен дополнительному списанию с вашей подписки. Поэтому `cost_usd` остаётся пустым, а не нулевым. Условия доступа, лимиты и оплату проверяют в аккаунте провайдера.

Формат ответа проверяется дважды: CLI помогает сформировать JSON, затем платформа проверяет полную исходную схему. Для Codex адаптер переводит необязательные поля в допустимые варианты объектов и оставляет проверки уникальности и границ платформе. В одном объекте поддерживается до пяти необязательных полей; ссылки `$ref` предварительно раскрывают в явную схему. Эти ограничения проверяются до обращения к модели.

Ошибки не содержат необработанный вывод CLI, адрес аккаунта или токены. Рабочий процесс обращается только к локальному адресу платформы, не следует перенаправлениям и не передаёт свой пропуск дочернему CLI. Автоматическая установка пакетов и обход подтверждений не используются.

## Личный доступ

Учебный переключатель сотрудников показывает, как меняется видимость по роли. Для локального входа без переключателя задайте `AUTH_MODE=token`; в `PERSON_TOKENS` укажите JSON-объект «длинный случайный токен → идентификатор сотрудника». Сохраните его только в `.env` и перезапустите платформу. API принимает `Authorization: Bearer <токен>`, а `X-Person` не меняет пользователя. Личный токен, токен запуска агента и пропуск рабочего процесса имеют разные назначения.
