# Добавить своего агента

Агент — отдельная программа. Платформа проверяет, кто её запускает, какие знания выдавать и соответствует ли результат договорённому формату.

1. Скопируйте `agents/_template/` в `agents/my-agent/`.
2. В `agent.yaml` поменяйте имя на `my-agent`, описание, владельца, роли, разделы знаний и схемы входа/выхода. JSON Schema — проверяемое описание полей и их типов. В коде замените имя в `@agent(...)`.
3. Напишите логику в `agent.py`. `ctx.get('clients')` получает доступные записи; `ctx.search('cases', 'торговля')` ищет; `ctx.llm(...)` обращается к модели через платформу. В настоящем режиме имя операции для `ctx.llm()` может быть своим, например `summarize_client`. Для нового типа операции в demo добавьте явный тестовый ответ в `platform/app.py: demo_response`; иначе получите понятный отказ. Не добавляйте ключ модели агенту.
4. Измените 3 примера в `tests/cases.json`. Проверяйте содержательный результат, отсутствие закрытых данных и ошибочный вход. Корневой тестовый набор обнаруживает эти файлы.
5. В `compose.yaml` скопируйте сервис `client-brief`, назовите `my-agent`, задайте `AGENT_NAME: my-agent`. Добавьте отдельную внутреннюю сеть `my-agent: {internal: true}` и подключите к ней только новый сервис и платформу. В `platform.environment.AGENT_URLS` добавьте `"my-agent":"http://my-agent:8000"`, в `platform.depends_on` — новый сервис.
6. Выполните `docker compose up --build -d --wait`, затем `make test`. Откройте карточку в «Агенты и модели», запустите пример и проверьте журнал.

Каждый шаг можно поручить Claude Code обычным русским запросом. Дайте ему эту инструкцию и требование сохранить работающие примеры.

`agent.yaml` разрешает запрашивать раздел, но не расширяет права человека. Если агент объявил `costs`, у sales всё равно не появится себестоимость. Необъявленный раздел даёт отказ. Токен запуска перестаёт работать после завершения и не позднее 15 минут.

Папка `_template` не регистрируется как рабочий агент. Добавление папки не поднимает новый Docker-сервис автоматически: поэтому шаг 5 обязателен.

Форма в браузере поддерживает строки, числа, целые числа, логические поля и перечисления. Объекты и массивы вводятся как JSON. Составные схемы (`oneOf`, `anyOf`, ссылки `$ref`, nullable-поля) явно обозначаются как неподдерживаемые формой; такой вход можно передать через Run API. Для первого агента используйте простую схему из шаблона.
