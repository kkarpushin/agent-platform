# Добавить отдельного агента

Для анализа или нового формата текста сначала попробуйте [добавить скилл](add-skill.md). Отдельный агент нужен для своей программы, вычислений, инструментов или последовательности действий.

1. Скопируйте `agents/_template/` в `agents/my-agent/`.
2. Измените имя в `agent.yaml` и `@agent(...)`, описание, владельца, роли, разделы, схемы входа и выхода. Для чтения задач и сообщений объявите `workspace: true` (в шаблоне уже указано); права на проекты всё равно проверяет платформа. Если используете `output-schema.json`, поддерживайте его в согласии с манифестом.
3. Напишите логику. `ctx.get('rules')` получает разрешённые записи; `ctx.search('projects', 'Орбита')` ищет; `ctx.workspace()` читает допустимое состояние; `ctx.llm(...)` обращается к настоящей модели через платформу. Не добавляйте авторизацию CLI агенту. Новым методам состояния нужны серверные проверки.
4. Создайте содержательные примеры в `tests/cases.json` и проверки: нормальный вход, отсутствие данных, роль, неверный выход. Для изолированных тестов новый модельный шаг получает контролируемый ответ в тестовом коде; это не основной режим приложения.
5. Добавьте отдельный сервис Compose по образцу `daily-brief`, `AGENT_NAME`, отдельную внутреннюю сеть только с платформой, адрес в `AGENT_URLS` и зависимость готовности. Папка сама по себе не создаёт сервис.
6. Перезапустите командой `python3 scripts/start.py --provider claude` (или codex), выполните изолированные тесты, запустите агент из интерфейса и проверьте трассировку.

Схема — правила полей, а не доказательство истинности. `agent.yaml` не расширяет права человека. Необъявленный раздел недоступен; токен завершённого запуска больше не действует. Изменение задач реализуется через проверяемый процесс и решение человека, а не прямую запись агента в базу.

Форма поддерживает строки, числа, логические поля и перечисления. Объекты и массивы вводятся как JSON. Составные схемы явно обозначаются как неподдерживаемые формой; используйте простой вход или API.
